## Threat model
The adversary is a prompt-injected or misaligned agent session, or a malicious contributor, with write access to the working tree. Its goals are to (a) land bytes in a protected or security-tier file through a path the write gate allows, or (b) clear a quarantined security-tier edit without a human.

## What changed, security-wise
- **Write gate (bug 9).** `norm_rel` now comes from the lexical path, not the resolved one. A symlinked final component (live or dangling) is refused, and so is a dangling directory component. On 5c2d698, `CLAUDE.md -> conductor/guardrails.md` let a write overwrite security-tier doctrine. My probes at the head refused that case, the case-variant name (APFS), the trailing-slash and `./` spellings, and nested directory links. `guarded_remove` no longer deletes a link's target.
- **approve.** It now requires a TTY on stdin and stdout, plus the typed-back path. This is honestly scoped as a presence check. I reproduced a pty bypass (LOW, see findings). It is still strictly better than 5c2d698, which had no check.
- **eng-b multi-entry status.** Capture quarantines a whole group when any entry in it is security tier. Approve, publish, override and reset act on the whole group, and doctor/update fail on mixed statuses.
- **render_outputs.** The section is additive. Render writes still go through `guarded_write`. A render output outside `owned_globs` is skipped rather than widening the gate.
- **Gate, verdict, policy, key registry and workflows.** Unchanged against main.

## Residual risk
- Local `approve` is not a trust boundary; the ship gate is.
- Hook and config render outputs are normal tier.
- The template engine copy is not gate-protected (deferred to v0.2.1).
- The P0 type-swap gate bypass (#71 lineage) is still open in v0.2.0.
- This approval is signed with an agent-held verifier key. Custody hardening is the first v0.2.1 item.
