# Cyra security verdict: PR #194 (v0.2.0 train: ws-upd, update adopts core-only upstream files)

Signed contract: the YAML front-matter above. The signature covers only the front-matter. This body is the human-readable record.

- Head reviewed: `c41827504dbe4ce7508c945e163d618165259373` (base `5c2d698`)
- Scope: the full diff, 4 paths. That is the engine, its template copy, and the new test plus its template copy.
- Security verdict: **CLEAR** (disposition APPROVE). Findings: 0 critical, 0 high, 0 medium, 5 low.

## Threat model
`tessctl update` is a supply-chain surface. It takes bytes from a remote signed tag and writes them into the operator's tree. I considered three adversaries. First, an attacker on the fetch path, who is stopped by signed-tag verification. Second, a hostile or buggy signed release that crafts `tess.lock` entries to escape `.tess/core`, reach live or never_touch paths, or overwrite local edits. Third, a local writer who plants symlinks so that A2 writes through them.

## What changed, security-wise
- A2 now adopts `live_path: null` entries: it copies the core file and adds the lock entry. Before this, they were silently skipped.
- The core key is gated. It must sit under `.tess/core/` and pass manifest never_touch. It must also pass `check_manifest_write_gate` with only `.tess/core/**` owned, which covers absolute paths, `..`, out-of-root resolution, symlinked parents, and the `.git`, vault and `.local.md` hard guards. On 5c2d698 the core write had none of these checks.
- The staged bytes must equal the upstream `base_sha`. A staged symlink or a missing staged file is refused.
- A core file that already exists with different bytes, or as a symlink, is kept and never overwritten. If the bytes are equal, A2 adds only the lock entry.
- A live path already tracked by other entries is never written, and the new entry takes that path's status. A published CLAUDE.md survives. On 5c2d698 it was overwritten.
- A new live path is written only if it is absent. An existing file or symlink there is kept, and doctor then reports it as drift.

## Residual risk
- The never_touch check is keyed on the raw lock key, so the `./` and `//` aliases bypass it. Containment still holds, and no shipped manifest fences `.tess/core`.
- A malformed signed lock (non-string live_path) crashes update mid-run and leaves a CORE-TAMPER state that needs a rollback. This predates the PR.
- The supply-chain refusals hold today but have no regression tests.
- The trust root is still the agent-held upstream signing key and this agent-held verifier key. Custody hardening is the first v0.2.1 item.
