## Why this registry exists

Autonomous or long-lived work (a background job, a multi-session build, an
agent loop) can silently stall or die between sessions with nothing forcing
anyone to notice — the only way to catch it is luck: a later session happening
to touch the same area. This registry exists so "is this project still
moving?" is answered from re-checked evidence (a commit, a PR, a file mtime),
never from memory or a self-report.

Two disciplines this registry — and the heartbeat that reads it
(`scripts/heartbeat/`) — are built to enforce:

1. **Every `resume:` recipe on a card starts "fresh clone from origin
   HEAD"** — never "continue from the local copy." A stale local clone
   sitting on disk is a resume trap: it looks like progress but silently
   works from old code.
2. **Every mutable-state claim carries a `last_verified` timestamp and a
   `verify_via` pointer** (the exact command that would re-confirm it — e.g.
   `gh pr list --repo ... --state open`, `git log -1`). A claim without both
   is a hypothesis to re-check, not a fact to act on.
